# Crawler MCP 使用技巧总览

> 基于 `pyppeteer + CDP` 的浏览器控制与逆向调试 MCP 服务

## 一、项目定位

Crawler MCP 主要解决四类问题：

1. 真实浏览器控制
2. 网络请求监听与拦截
3. 断点调试与页面内表达式求值
4. 标准化 JS 逆向流程与本地补环境复现

当前核心实现只有两部分：

- [server.py](D:/网易/crawler-mcp/server.py)：MCP 工具注册入口
- [browser.py](D:/网易/crawler-mcp/browser.py)：Chrome/CDP 控制与调试能力

## 五、推荐工作流

### 1. 抓接口

```text
open_browser
-> clear_captured_requests
-> 手动触发页面操作
-> get_captured_requests
-> get_response_body
-> 大响应体使用 save_response_body 落盘
-> start_action_recording
-> 执行页面动作
-> stop_action_recording
-> replay_actions
-> replay_and_capture 绑定动作与请求证据
```

### 2. 断点看签名

```text
open_browser
-> set_xhr_breakpoint
-> 刷新或触发请求
-> debugger_get_call_stack
-> debugger_evaluate
-> debugger_step_into / debugger_step_over
```

### 3. 页面内验证补环境

```text
execute_js
-> 查看真实浏览器对象类型和属性
-> 本地脚本按缺失项最小补环境
-> 再次 execute_js 验证
```

### 4. 标准逆向任务

```text
先填 task-input-template
-> 复制 artifacts/tasks/_TEMPLATE
-> 页面取证
-> 本地复现
-> 补环境推进 first divergence
-> 输出 report
```

## 六、补环境注意点

- 先通过吐环境脚本定位 `undefined`
- 再到真实浏览器里用 `execute_js` 查类型、描述符、原型链
- 补最小可运行环境，不要一口气照搬整份 `env.js`
- 如果补的是 DOM 对象，优先保证原型链关系正确
- 所有自定义函数都要做 `safeFunction` 伪装
- 重点记录当前 `first divergence`
- 每次只做一个补丁决策
- 临时 Hook、代理、断点和注入脚本必须有清理动作
- 登录态原始请求证据可保留在受控任务目录；不要为了“脱敏”破坏复现所需的 Cookie、Authorization 或设备态

## 七、任务产物模板

如果任务不是一次性对话，而是要持续推进、沉淀或交接，先复制：

- [artifacts/tasks/_TEMPLATE](D:/网易/crawler-mcp/artifacts/tasks/_TEMPLATE)
- 样例参考：[xhs-search-xs-20260423](D:/网易/crawler-mcp/artifacts/tasks/xhs-search-xs-20260423)

其中：

- `task.json` 记录任务状态
- `network.jsonl` 记录请求链路
- `runtime-evidence.jsonl` 记录 hook / 断点证据
- `scripts.jsonl` 记录脚本和函数线索
- `env/` 放本地补环境
- `run/` 放本地运行入口
- `report.md` 记录阶段结论

## 九、文档校验

修改工具注册或技能文档后运行：

```powershell
& D:\\网易\\crawler-mcp\\utils\\validate_skill_docs.ps1
```

脚本会检查：

- 浏览器文档工具名是否已在 `server.py` 注册；
- Markdown 代码块是否成对；
- 文档中的本地绝对链接是否存在。

导出当前真实 MCP 工具清单：

```powershell
python D:\\网易\\crawler-mcp\\utils\\export_mcp_tools.py --format markdown
```

该清单从 `server.py` 的 AST 提取，不启动 MCP 服务，也不依赖运行时浏览器。
