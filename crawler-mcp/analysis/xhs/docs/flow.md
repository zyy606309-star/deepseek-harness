# 小红书专题链路整理

## 目标

沉淀一套可复用的小红书 Web 侧分析与请求链路，用于：

1. 观察接口与签名生成路径
2. 在真实浏览器中验证签名行为
3. 在 Node 侧补环境执行签名逻辑
4. 由 Python 侧发起业务请求

## 文件职责

### core/code.js

小红书签名核心代码样本。

作用：

1. 用于定位签名入口
2. 用于抽离签名逻辑
3. 用于补环境后的本地执行

### core/env.js

Node 侧补环境文件。

原则：

1. 以最小可用为主
2. 必须结合真实浏览器验证
3. 不要直接从旧项目整段照抄

### core/sign.js

本地签名执行入口。

通常负责：

1. 加载补环境
2. 加载签名核心代码
3. 暴露统一签名函数

### spider/homefeed.py

首页推荐流请求脚本。

### spider/search.py

搜索接口请求脚本。

## 标准链路

### 链路 A：真实浏览器验证

适用场景：

1. 确认签名入口
2. 确认请求参数
3. 确认 `X-s / X-t / X-s-common` 行为

标准步骤：

1. 在真实浏览器打开小红书页面
2. 监听目标接口
3. 对目标请求打断点或抓包
4. 查看调用栈
5. 确认签名函数与输入参数

### 链路 B：Node 侧补环境签名

适用场景：

1. 批量化请求
2. 自动化脚本
3. 脱离浏览器生成签名

标准步骤：

1. 从浏览器提取核心代码
2. 在 `core/env.js` 中补环境
3. 用 `core/sign.js` 验证签名输出
4. 用 `spider/*.py` 发起业务请求

## 当前方法论结论

1. 浏览器链路用于确认真实行为。
2. Node 链路用于复现和批量化。
3. 先确认参数和调用路径，再补环境。
4. 不要把“日志里看到的函数名”直接等同于“真正关键点”。
5. 如果某条请求链路已经稳定跑通，应优先固化成功链路。
