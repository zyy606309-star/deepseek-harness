# JavaScript 补环境

> 这份文档解决两个问题：
> 1. 补环境时应该先做什么、后做什么
> 2. 遇到具体缺口时，应该怎么补、怎么验证、怎么回退

---

## 一、目标

补环境的目标不是：

1. 把所有 `undefined` 都补掉
2. 把 `env.js` 写得很长
3. 从别处抄一整份浏览器环境

补环境的目标是：

1. 让当前脚本在当前页面输入下继续往后执行
2. 让本地执行路径逐步逼近真实浏览器
3. 让最终产物和浏览器产物对齐

---

## 二、总流程

补环境默认按下面顺序做，不要跳步骤：

```text
1. 准备最小模板
2. 接入吐环境脚本
3. 运行脚本，记录 undefined 和关键函数参数
4. 去真实浏览器核对
5. 只补当前确认过的一项
6. 立刻重跑
7. 看 first divergence 是否后移
8. 如果结果变差，撤回刚才的补丁
9. 重复 3-8
```

一句话版本：

```text
先观察 -> 再核对 -> 再补 -> 再验证
```

---

## 三、核心原则

1. 原型链必须完整到当前调用路径所需的层级。
2. 只有存在函数外形检测证据时才使用 `safeFunction`；没有证据时优先保留原生函数行为。
3. 先看日志，再决定补什么。
4. 必须去真实浏览器核对，不允许纯猜。
5. 一次只补一个明确点。
6. 补错比漏补更危险。
7. 页面动态输入也是环境的一部分。
8. 成功链路优先于想象中的链路。

---

## 四、起步模板

> 安全边界：下面的模板只允许放在独立的 Node 子进程或 `vm` context 中运行。不要在 MCP 服务进程、长期运行的 Python 宿主或共享 Node 进程里直接改写 `Function.prototype`、`global` 和 `window`。

### 4.1 safeFunction

```javascript
!(function () {
    const $toString = Function.prototype.toString;
    const symbol = Symbol();
    const myToString = function () {
        return typeof this === "function" && this[symbol] || $toString.call(this);
    };
    function setNative(target, key, value) {
        Object.defineProperty(target, key, {
            enumerable: false,
            configurable: true,
            writable: true,
            value,
        });
    }
    delete Function.prototype.toString;
    setNative(Function.prototype, "toString", myToString);
    setNative(Function.prototype.toString, symbol, "function toString() { [native code] }");
    globalThis.safeFunction = function (func, funcname) {
        setNative(func, symbol, `function ${funcname || func.name || ""}() { [native code] }`);
        return func;
    };
})();
```

`safeFunction` 只用于被目标脚本主动检查 `Function.prototype.toString` 的实验场景。若没有证据表明存在这类检查，优先保留原生函数外形，不要默认伪造 `[native code]`。

### 4.2 隐藏 Node 痕迹

```javascript
delete __filename;
delete __dirname;
window = global;
delete global;
window.window = window;
window.self = window;
window.top = window;
```

这段代码会破坏宿主脚本的调试和模块行为，不应作为通用补丁直接复制。先记录目标脚本实际读取了哪些 Node 痕迹，再在隔离上下文中逐项处理。

### 4.3 最小起步对象

```javascript
document = {};
location = {};
navigator = {};
history = {};
screen = {};
```

说明：

1. 这只是起步模板，不是最终答案。
2. 起步阶段只要求“脚本开始访问环境”。
3. 不要一上来补一大堆字段。

## 五、吐环境脚本

代理日志只记录访问路径、操作类型和返回类型；默认不要打印 Cookie、Token、完整请求体或大段脚本。日志应限流，并且每次补丁后清空旧日志。

先把这段接进去，再跑脚本：

```javascript
function getEnv(proxyArray) {
    for (let i = 0; i < proxyArray.length; i++) {
        const handler = `{
            get: function(target, property, receiver) {
                console.log('方法：get','    对象：${proxyArray[i]}','    属性：',property,'    属性类型：',typeof property,'    属性值类型：',typeof target[property]);
                return target[property];
            },
            set: function(target, property, value, receiver) {
                console.log('方法：set','    对象：${proxyArray[i]}','    属性：',property,'    属性类型：',typeof property,'    属性值类型：',typeof target[property]);
                return Reflect.set(...arguments);
            }
        }`;
        eval(`
            try {
                ${proxyArray[i]};
                ${proxyArray[i]} = new Proxy(${proxyArray[i]}, ${handler});
            } catch (e) {
                ${proxyArray[i]} = {};
                ${proxyArray[i]} = new Proxy(${proxyArray[i]}, ${handler});
            }
        `);
    }
}

proxyArray = ["window", "document", "location", "navigator", "history", "screen"];
getEnv(proxyArray);
```

### 5.1 优先看什么

先看这三类信息：

1. `方法：get ... 属性值类型： undefined`
2. 哪个关键函数被调用了
3. 关键函数传了什么参数

不要先看报错堆栈就直接补。
报错堆栈只用来辅助定位，不用来代替环境核对。

### 5.2 证据记录格式

每个缺口至少记录：

```text
对象路径:
操作: get / set / call / construct
参数摘要:
真实浏览器类型与挂载层级:
本地返回:
补丁:
补丁后 first divergence:
删除补丁后的回归结果:
```

## 六、关键函数先打参数日志

很多时候，先看参数比先补返回值更重要。

优先给这些函数加日志：

1. `document.createElement`
2. `document.getElementById`
3. `document.getElementsByTagName`
4. `Element.prototype.getElementsByTagName`
5. `Element.prototype.setAttribute`
6. `appendChild`
7. `removeChild`
8. `history.replaceState`
9. `window.eval`
10. `window.Function`

### 6.1 通用写法

```javascript
function logCall(name, fn) {
    return function (...args) {
        console.log(`[CALL] ${name}`, args);
        return fn.apply(this, args);
    };
}
```

包装函数必须保留 `this`、参数、异常和返回值；不要用空函数吞掉异常，否则会把真实分叉点推迟到更难定位的位置。

### 6.2 直接写法

```javascript
Document.prototype.getElementById = safeFunction(function getElementById(id) {
    console.log("Document.getElementById 参数:", id);
    return null;
}, "getElementById");
```

```javascript
Element.prototype.setAttribute = safeFunction(function setAttribute(name, value) {
    console.log("Element.setAttribute 参数:", name, value);
    this[name] = value;
}, "setAttribute");
```

### 6.3 为什么先打参数

因为你要先回答这些问题：

1. 它到底是不是走了这条路径
2. 它查的是哪个标签、哪个 id、哪个属性
3. 它是“只看有没有”还是“真的依赖返回内容”

参数不清楚时，不要急着补复杂对象。

## 七、去真实浏览器怎么核对

必须去浏览器确认下面这些东西：

1. 值
2. 类型
3. 挂载层级
4. 描述符
5. 原型链
6. 对象外形

### 7.1 推荐核对顺序

```javascript
typeof document.cookie
document.cookie
```

```javascript
document.hasOwnProperty("cookie")
Document.prototype.hasOwnProperty("cookie")
```

```javascript
Object.getOwnPropertyDescriptor(Document.prototype, "cookie")
```

```javascript
let obj = document;
let chain = [];
while (obj) {
  chain.push(obj.constructor && obj.constructor.name);
  obj = Object.getPrototypeOf(obj);
}
chain
```

### 7.2 要特别确认什么

不要只确认“有没有这个字段”，还要确认：

1. 它是普通值、函数、getter 还是构造函数
2. 它挂在实例上还是原型上
3. 它返回的是空对象、数组、集合还是具体标签

---

## 八、怎么补一个缺口

看到一个缺口后，默认按这个顺序做：

### 8.1 第一步：先记录

记录四件事：

1. 是哪个对象缺东西
2. 是读、写，还是调用
3. 是不是链式访问
4. 有没有参数

例如：

```text
方法：get     对象：document     属性： getElementById     属性值类型： undefined
```

或者：

```text
div get: load type: undefined
```

### 8.2 第二步：去浏览器核对

看它在浏览器里到底是什么：

1. `typeof`
2. `hasOwnProperty`
3. `Object.getOwnPropertyDescriptor`
4. 原型链位置

### 8.3 第三步：只补这一项

值就按值补：

```javascript
window.name = "";
```

函数就按函数补：

```javascript
history.replaceState = safeFunction(function replaceState() {}, "replaceState");
```

getter 就按 getter 补：

```javascript
Object.defineProperty(Document.prototype, "visibilityState", {
    configurable: true,
    enumerable: true,
    get: safeFunction(function visibilityState() {
        return "visible";
    }, "get visibilityState")
});
```

### 8.4 第四步：立刻重跑

看三件事：

1. 原缺口是否消失
2. 新缺口是否后移
3. 执行是否明显变差

---

## 九、DOM 标签对象怎么补

很多时候缺的不是全局对象，而是 `document.createElement(tag)` 返回的标签对象本身。

默认做法：

1. 给目标标签建类
2. 让 `createElement(tag)` 返回该实例
3. 只代理这个实例
4. 看后续到底访问了什么

### 9.1 示例

```javascript
function HTMLDivElement() {}
safeFunction(HTMLDivElement);
Object.setPrototypeOf(HTMLDivElement.prototype, HTMLElement.prototype);

div = new Proxy(new HTMLDivElement(), {
    get(target, property, receiver) {
        console.log("div get:", property, "type:", typeof target[property]);
        return Reflect.get(target, property, receiver);
    },
    set(target, property, value, receiver) {
        console.log("div set:", property, "oldType:", typeof target[property], "newType:", typeof value);
        return Reflect.set(target, property, value, receiver);
    }
});

Document.prototype.createElement = safeFunction(function createElement(tagName) {
    console.log("document createElement 创建的标签为:", tagName);
    if (String(tagName).toLowerCase() === "div") {
        return div;
    }
    return new HTMLElement();
}, "createElement");
```

### 9.2 这个方法解决什么问题

它主要用来判断：

1. 真正缺的是哪个标签
2. 是要补实例，还是补原型
3. 后续访问的是 `style`、`setAttribute`、`load`、`save` 还是别的东西

## 十、集合类接口怎么补

这是最容易补错的一类。

### 10.1 默认策略

下面这些接口，默认优先返回“空但结构正确”的集合：

1. `getElementsByTagName`
2. `querySelectorAll`
3. `children`
4. `forms`
5. `scripts`

### 10.2 结构模板

```javascript
function makeCollection(items) {
    const collection = {
        length: items.length,
        item: safeFunction(function item(index) {
            return items[index] || null;
        }, "item")
    };
    for (let i = 0; i < items.length; i++) {
        collection[i] = items[i];
    }
    return collection;
}
```

### 10.3 为什么默认返回空集合

因为空集合和非空集合会直接改变执行分支。

下面这两种不是“细节不同”，而是“业务路径不同”：

```javascript
if (lowerTagName === "i") {
    return makeCollection([]);
}
```

```javascript
if (lowerTagName === "i") {
    return makeCollection([iElement]);
}
```

非空集合很可能直接把脚本带进错误的深分支。

### 10.4 什么时候允许改成非空

只有同时满足这三个条件，才允许把空集合改成非空：

1. 已确认代码真的依赖“有元素”
2. 已确认应该返回哪类元素
3. 已确认非空不会把路径带偏

否则一律先返回空集合。

### 10.5 先分支，再差异化

可以先打参数日志，但不急着返回真实元素：

```javascript
Element.prototype.getElementsByTagName = safeFunction(function getElementsByTagName(tagName) {
    console.log("Element.getElementsByTagName 参数:", tagName);
    return makeCollection([]);
}, "getElementsByTagName");
```

确认参数稳定后，再考虑是否按标签名分支。

## 十一、动态输入也是环境的一部分

下面这些不是“附属数据”，而是环境本身：

1. `meta content`
2. 首包 cookie
3. 内联脚本
4. 外链脚本 URL
5. 外链脚本内容
6. JS 运行后生成的 cookie

如果这些值和当前页面不匹配，环境补得再像也没用。

### 11.1 正确做法

运行流程应该是：

1. 先请求真实页面
2. 提取当前页动态输入
3. 更新 `env.js / code.js / decode.js`
4. 再执行 Node 补环境脚本

### 11.2 不正确做法

不要：

1. 留着旧的 `content`
2. 留着旧的 cookie
3. 用旧页面的内联脚本跑新页面

## 十二、日志限流

如果某个字段会高频触发，比如 `innerHTML`，要限流，不然看不到真正的新缺口。

### 12.1 示例

```javascript
function makeElementLogger(name, target) {
    const logState = Object.create(null);
    return new Proxy(target, {
        get(currentTarget, property, receiver) {
            console.log(name + " get:", property, "type:", typeof currentTarget[property]);
            return Reflect.get(currentTarget, property, receiver);
        },
        set(currentTarget, property, value, receiver) {
            const key = String(property);
            if (key === "innerHTML") {
                logState[key] = (logState[key] || 0) + 1;
                if (logState[key] <= 5) {
                    console.log(name + " set:", property, "oldType:", typeof currentTarget[property], "newType:", typeof value);
                } else if (logState[key] === 6) {
                    console.log(name + " set:", property, "日志过多，后续同类输出已省略");
                }
                return Reflect.set(currentTarget, property, value, receiver);
            }
            console.log(name + " set:", property, "oldType:", typeof currentTarget[property], "newType:", typeof value);
            return Reflect.set(currentTarget, property, value, receiver);
        }
    });
}
```

## 十三、怎么判断补对了

补对的信号：

1. 原来的 `undefined` 消失
2. 新缺口出现在更后面
3. 原来直接报错，现在能继续执行
4. 成功链路变长
5. 删除该补丁后结果立刻退化

补错的信号：

1. 补完后进入明显不同的错误分支
2. 开始出现高频循环日志
3. 原来能结束，现在结束不了
4. 输出反而更不像浏览器

一旦出现补错信号，先撤回刚才的补丁，不要硬着头皮继续往下补。

## 十四、first divergence

补环境时，要持续观察一个东西：

```text
first divergence
```

意思是：

```text
本地运行结果和真实浏览器第一次出现分叉的位置
```

### 14.1 你每次补丁之后都该问自己

1. 分叉点后移了吗
2. 分叉点是否更明确了
3. 这次补丁是否真的缩小了问题范围

如果连续多轮补丁都没有推动 `first divergence` 后移，就该停下来回到浏览器重新取证。

## 十五、常见错误

### 15.1 看到 undefined 就立刻补

错误：

```text
window.xxx => undefined
```

然后直接：

```javascript
window.xxx = {};
```

正确做法：

先看浏览器里它到底是不是 `undefined`。

### 15.2 把实例字段补到原型上

错误：

```javascript
Document.prototype.body = {};
```

正确做法：

先确认它到底挂在哪一层。

### 15.3 getter 补成普通值

错误：

```javascript
Document.prototype.cookie = "";
```

正确做法：

先看描述符，再按 getter/setter 补。

### 15.4 集合接口直接返回非空元素

这是最危险的误补之一。

正确做法：

先返回空集合，先看参数和分支，再决定是否改非空。

### 15.5 一次性补太多

错误：

一次补十几个字段，然后不知道哪一个真正起作用。

正确做法：

一次只补一个明确点，或者一段必须成套出现的原型链。

---

## 十六、最终检查清单

准备结束补环境前，至少确认下面这些事：

1. 关键入口函数已经定位清楚
2. 当前动态输入与当前页面匹配
3. 原型链已经补到够用的位置
4. 集合类接口没有乱补成非空
5. 没有高频日志风暴
6. 请求链路可以稳定复现
7. 本地产物与浏览器产物已经对齐或接近对齐
