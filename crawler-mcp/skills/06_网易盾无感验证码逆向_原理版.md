> 使用 MCP 工具分析网易易盾无感验证码的完整方法论

> 这是某一版本 YiDun 无感流程的成功样本。接口路径、参数首次出现位置和编码细节都可能随 SDK、业务接入方式和时间变化，开始新任务时必须重新抓链路。

## 一、文档定位

本文档负责：

- 解释完整链路和逆向目标
- 记录 `cb`、`data.m/p/ext` 的分析方法
- 给出完整实现应覆盖的关键步骤

本文档不负责：

- 控制 LLM token 消耗
- 规定分阶段最小采集范围
- 提供可直接复制的提示词

配套文件：

- 执行版：`07_网易盾无感验证码逆向_执行版.md`
- 提示词版：`08_网易盾无感验证码逆向_提示词版.md`

推荐使用顺序：

1. 先用本文档理解整体链路
2. 实操时切换到执行版
3. 和 AI 多轮协作时使用提示词版

## 二、适用场景

当遇到网易易盾（YiDun）无感验证码时，需要逆向以下参数：
- `fp` - 设备指纹
- `cb` - 请求签名
- `data.m/p/ext` - 行为数据

```json

// 2. 触发验证码
```

**需要关注的接口**：
| 接口 | 方法 | 用途 |
|------|------|------|
| `/api/v2/getconf` | JSONP | 获取配置 |
| `/v4/j/up` | POST | 上传设备指纹 |
| `/api/v3/get` | JSONP | 获取 token |
| `/api/v3/check` | JSONP | 提交验证 |

不要只凭路径判断链路完整性；同时记录请求方法、回调参数、状态码、响应类型和参数首次出现的位置。

## 八、常见问题排查

### 7.1 参数生成错误

| 问题 | 排查方法 |
|------|---------|
| cb 长度不对 | 检查 Base64 字符集和填充字符 |
| 验证失败 | 检查 S-Box 是否完整（256字节） |
| 时间相关错误 | 检查 fp 中的时间戳 |

### 7.2 版本更新

SDK 版本从文件名获取：`core-optimi.{suffix}.v{version}.min.js`

需要重新提取的常量：
- `SEED_KEY`
- `S-Box`
- `变换序列`
- `code` / `suffix`
- `Base64字符集`
