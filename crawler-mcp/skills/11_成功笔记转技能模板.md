# 成功笔记转技能模板

> 用于把一次已经成功的逆向记录，整理成可重复、可验证、可迁移的技能文档。成功不等于通用；先拆事实，再提炼规则。

## 一、元数据

```text
任务名称:
目标类型: Web / APP / 协议 / JS / 其他
目标 URL 或包名:
目标版本:
浏览器 / Android / Node / Python 版本:
分析日期:
原始证据目录:
原始文件哈希:
```

## 二、结论分层

### 已确认事实

只写能够由请求、日志、断点、文件或运行结果直接证明的内容。

```text
- 观察到什么:
- 证据位置:
- 复现次数:
- 是否跨版本验证:
```

### 当前推断

写出推断依据和置信度，不要把变量名、函数名或经验规则写成事实。

```text
- 推断:
- 依据:
- 置信度: high / medium / low
- 还缺什么证据:
```

### 未验证假设

明确列出尚未证明的路径，避免后续读者误用。

## 三、最小复现

```text
前置条件:
触发动作:
输入样本:
关键命令:
关键工具:
预期输出:
成功判据:
```

最小复现必须包含输入、输出和成功判据。只写“运行脚本成功”不算验证；要说明是返回值、请求结果、业务页面还是结构化字段发生了什么变化。

## 四、标准流程

1. Observe：目标、动作、请求、脚本和运行时范围。
2. Capture：生成点、调用参数、响应摘要和时间窗口。
3. Rebuild：浏览器与本地同输入对照。
4. Patch：一次只改一个最小因果单元。
5. Verify：回归样本、失败样本和删除补丁后的退化结果。

## 五、失败与回退

```text
失败现象:
first divergence:
已排除项:
最后一次有效状态:
回滚命令或文件:
下一步最小动作:
```

不要只记录最后的成功路径。失败路径决定这份技能以后能否快速定位问题。

## 六、版本与迁移边界

```text
已验证版本:
未验证版本:
稳定标识:
易漂移字段:
每次版本更新必须重新确认:
```

接口路径、Cookie 名称、模块 ID、混淆变量名、时间窗口和环境字段默认都属于易漂移内容，除非已有跨版本证据。

## 七、输出与证据索引

```text
原始请求:
响应体或摘要:
脚本/模块:
运行日志:
截图或断点:
最终报告:
```

证据文件与摘要分开保存。摘要可以压缩上下文，但不能替代原始证据。

## 八、技能化检查清单

- [ ] 目标、版本、环境和证据目录已记录
- [ ] 已确认事实、推断和假设已分开
- [ ] 有最小输入、输出和成功判据
- [ ] 有失败条件、first divergence 和回退动作
- [ ] 已标注版本边界和易漂移字段
- [ ] 代码示例不会把未转义输入拼进源码
- [ ] 临时 Hook、代理、注入和调试状态有清理方法
- [ ] 文档中的工具名与当前 MCP 注册一致
- [ ] 至少有一条浏览器/运行时同输入回归样本
- [ ] 登录态原始证据保留在受控目录，报告和摘要没有无必要地展开凭证

## 九、从笔记提升为规则的门槛

只有满足以下条件，成功笔记中的经验才可以写成无条件规则：

1. 至少两次同版本复现；或有跨版本对照；
2. 有明确的反例或适用边界；
3. 能提供最小复现和回滚方式；
4. 结论不依赖偶然的变量名、模块 ID 或单个时间窗口。

否则使用“常见特征”“当前样本”“待验证假设”等措辞。
