## 二、统一决策顺序

```text
目标和触发动作
  -> 真实运行时观察
  -> 请求/调用点取证
  -> 判断是现有实现可复用、局部修复还是重新逆向
  -> 最小本地复现
  -> 单变量修补
  -> 同输入回归
  -> 归档或停止
```

## 三、证据优先级

1. 真实请求/响应和运行时事件；
2. 断点处的实际参数、返回值和调用栈；
3. 同输入的浏览器/本地差异；
4. 静态脚本、模块结构和字符串；
5. 变量命名、历史笔记和经验特征。

越靠后越不能单独支撑强结论。

登录态处理原则：逆向复现阶段优先保留原始 Cookie、Authorization、设备标识和请求体，因为它们可能决定服务端是否接受请求。控制暴露面的方法是限制文件范围、限制模型上下文和限制交接复制，而不是破坏原始证据。

## 四、三种结论状态

### 可复用

有最小复现、成功判据、至少一组回归样本，并标明版本边界。

### 可参考

成功过，但依赖特定版本、特定页面状态或未完成跨版本验证。

### 仅线索

只有静态特征、单次现象或变量名推断，不能直接写进自动化脚本。

## 五、停止条件

满足任一项就停止当前分支：

- 目标参数已稳定产出并通过业务验证；
- 现有实现已验证可复用；
- 当前问题已明确属于另一个参数或另一个运行时；
- 连续两轮没有让 first divergence 后移；
- 新材料只增加长度，不增加结论确定性。
