# JS 逆向作业规范

> 本文档是本仓库的总纲型技能。站点专题技能开始前，先按这里的顺序定边界。

## 使用方式

这是一份执行规范，不是成功案例的复述。专题笔记中的结论只有在同时满足下面三点时，才允许上升为通用规则：

1. 有真实浏览器或运行时证据；
2. 有最小输入、输出和复现命令；
3. 有失败条件、版本范围和回退路径。

没有这些信息的内容，一律标记为“经验线索”，不能直接当成协议定论。

## 核心原则

- Observe-first
- Hook-preferred
- Breakpoint-last
- Rebuild-oriented
- Evidence-first

## 默认流程

1. Observe
2. Capture
3. Rebuild
4. Patch
5. DeepDive

每一阶段都必须有明确的进入条件、产物和停止条件。不要因为已经定位到一个可疑函数，就自动进入深挖。

详细说明见：

- [reverse-workflow.md](/D:/网易/crawler-mcp/docs/reference/reverse-workflow.md)

## 各阶段要求

### 1. Observe

先确认：

- 目标页面
- 目标请求
- 目标字段
- 触发动作
- 可疑脚本和函数范围

最小产物：目标 URL、触发动作、请求/响应标识、候选脚本 URL 或模块范围。

### 2. Capture

优先做：

- 网络监听
- 页面内 hook
- 必要时 preload

优先记录“生成点”和“调用参数”，其次才是完整脚本。每条证据都要带时间、触发动作和来源页面。

只有 hook 无法解释上下文时才进入断点。

### 3. Rebuild

目标不是完整模拟浏览器，而是先跑通目标参数链路。

参考：

- [reverse-artifacts.md](/D:/网易/crawler-mcp/docs/reference/reverse-artifacts.md)

先做浏览器与本地的同输入对照，再写等价实现。不要先凭函数名猜算法。

### 4. Patch

补环境默认遵循：

- 页面证据
- 代理 env log
- `first divergence`
- 最小因果单元

每个补丁都要回答：补了什么、为什么补、哪条证据支持、删除后是否退化。

参考：

- [env-patching.md](/D:/网易/crawler-mcp/docs/reference/env-patching.md)

### 5. DeepDive

本地跑通后，再做：

- 去混淆
- 控制流还原
- 算法提纯

只有当目标需要长期复用、性能或脱离浏览器运行时，才进入这一阶段。
