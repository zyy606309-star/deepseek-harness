## 二、请求签名分析

### 2.1 关键请求头

| 请求头 | 示例 | 说明 |
|-------|------|------|
| `X-s` | `XYW_eyJ...` | **核心签名**，Base64 编码的 JSON |
| `X-t` | `1711234567890` | 13位时间戳 |
| `X-s-common` | `...` | 公共签名（某些接口需要） |
| `X-b3-traceid` | `uuid` | 链路追踪 ID |

### 2.2 X-s 签名结构

```json
{
  "signSvn": "56",
  "signType": "x2",
  "appId": "xhs-pc-web",
  "signVersion": "1",
  "payload": "加密后的数据"
}
```

## 三、签名定位过程

### 3.1 使用 MCP 工具定位

```javascript
// 1. 启动真实浏览器
launch_real_chrome → wait_for_new_tab

// 2. 访问小红书
navigate → {"url": "https://www.xiaohongshu.com"}

// 3. 搜索签名关键字
search_in_js → {"keyword": "X-s"}
search_in_js → {"keyword": "_webmsxyw"}

// 4. Hook 签名函数
hook_function → {"function_path": "window._webmsxyw", "hook_type": "both"}

// 5. 触发请求后查看日志
get_hook_logs → {"limit": 10}
```

### 3.2 签名函数定位

签名入口函数：`window._webmsxyw(url, data)`

- **参数1**：API 路径，如 `/api/sns/web/v1/homefeed`
- **参数2**：请求体 JSON 字符串（POST 请求）或空字符串
- **返回值**：`{ "X-s": "...", "X-t": "..." }`

## 四、MCP 直接调用签名

> 当前 `crawler-mcp/server.py` 没有注册 `xhs_sign`、`xhs_decode_sign`、`xhs_api_request` 三个工具。下面内容应理解为外部脚本/待实现接口，不能直接通过本 MCP 调用。当前可用的底层工具是浏览器导航、页面 JS 执行、请求监听、响应体读取和调试器。

### 外部接口约定（非 crawler-mcp 内置工具）

以下三个名称来自成功案例中的上层封装，不属于当前 MCP 注册工具。需要使用时，先确认对应脚本或服务存在，再用当前 MCP 的底层浏览器/网络工具完成替代验证。

#### `xhs_sign`
外部签名脚本的接口约定：在已登录、版本匹配的浏览器上下文中生成签名。

```json
{
  "url": "/api/sns/web/v1/homefeed",
  "data": "{\"cursor_score\":\"\",\"num\":20}"
}
```

**返回**：
```json
{
  "X-s": "XYW_eyJ...",
  "X-t": "1711234567890"
}
```

#### `xhs_decode_sign`
外部分析脚本的接口约定。不要把签名字段当成稳定协议；每次版本变化都要用浏览器实际请求核对。

```json
{"xs": "XYW_eyJ..."}
```

#### `xhs_api_request`
外部请求脚本的接口约定。当前 MCP 不提供站点 API 直连工具。

```json
{
  "api_path": "/api/sns/web/v1/homefeed",
  "method": "POST",
  "data": {"cursor_score": "", "num": 20}
}
```

## 六、Python 请求示例

### 6.1 搜索接口

```python
import requests
import json
import time
import subprocess

def get_sign(url, data=''):
    """调用 Node.js 生成签名"""
    # 这里只适合本地实验；不要把未转义的 data 拼进 JavaScript 源码。
    # 生产实现应通过 stdin、临时 JSON 文件或结构化 Node 参数传递输入。
    result = subprocess.run(
        ['node', '-e', '''
            const originalLog = console.log;
            console.log = (...args) => process.stderr.write(args.join(' ') + '\\n');
            require('./xhs/core/env.js');
            require('./xhs/core/code.js');
            const fs = require('fs');
            const input = JSON.parse(fs.readFileSync(0, 'utf8'));
            process.stdout.write(JSON.stringify(window._webmsxyw(input.url, input.data)));
        '''],
        input=json.dumps({'url': url, 'data': data}, ensure_ascii=False),
        capture_output=True,
        text=True
    )
    if result.returncode != 0:
        raise RuntimeError(result.stderr.strip() or 'Node signer failed')
    try:
        return json.loads(result.stdout.strip())
    except json.JSONDecodeError as exc:
        raise RuntimeError(f'Invalid signer output: {result.stdout[:500]!r}') from exc

def search_notes(keyword, page=1):
    url = '/api/sns/web/v1/search/notes'
    data = json.dumps({
        "keyword": keyword,
        "page": page,
        "page_size": 20,
        "search_id": "",
        "sort": "general",
        "note_type": 0
    })

    sign = get_sign(url, data)

    headers = {
        'User-Agent': 'Mozilla/5.0...',
        'X-s': sign['X-s'],
        'X-t': sign['X-t'],
        'Content-Type': 'application/json',
    }

    response = requests.post(
        f'https://edith.xiaohongshu.com{url}',
        headers=headers,
        data=data,
        cookies={'a1': 'xxx'}  # 需要有效 cookie
    )

    return response.json()
```

### 6.2 验证要求

不能只看本地函数返回了 `X-s`。至少保存一组同时间窗口的浏览器请求与本地输出，核对：

1. 请求路径、方法和序列化后的 body 完全一致；
2. `X-t` 的生成时间与请求发送时间接近；
3. Cookie、User-Agent、Referer 和必要设备字段来自同一浏览器会话；
4. 服务端响应成功，且不是仅返回通用错误页。

## 七、常见问题

### 7.1 签名失效
- 检查 `X-t` 是否过期；有效窗口随接口和版本变化，不能固定写死 30 秒
- 检查 `a1` cookie 是否有效

### 7.2 返回 -1 错误码
- 缺少必要 cookie（`a1`, `webId`）
- 签名参数不匹配

### 7.3 补环境报错
- 按 `02_补环境.md` 流程逐步排查
- 确保 `safeFunction` 在最前面
